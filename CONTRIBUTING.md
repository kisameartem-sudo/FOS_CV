# Правила внесения изменений

## Общий принцип

Каждое изменение должно улучшать проверяемость результатов обучения, прозрачность оценивания или воспроизводимость материалов.

## Рабочий процесс

1. Создайте ветку `feature/<short-name>` или `fix/<short-name>`.
2. Вносите одно логически завершённое изменение за коммит.
3. Используйте сообщения вида `docs: update lab indicator matrix` или `fix: repair baseline link`.
4. Проверьте относительные ссылки, команды запуска и согласованность индикаторов.
5. В Pull Request перечислите затронутые КИМ, индикаторы и уровни.

## Требования к КИМ

- каждый рабочий КИМ, проект и экзамен должен содержать таблицу «индикатор — уровень — предметный дескриптор»;
- код индикатора указывается полностью: `DL-1.3`, `DL-3.2`, `PL-1.1`;
- в сводных таблицах код и уровень объединяются в одном поле: `DL-1.3 (Б)`;
- дескриптор должен описывать наблюдаемое действие, реально проверяемое заданием и критериями;
- максимальные баллы должны совпадать с моделью оценивания;
- внешние материалы должны иметь устойчивую ссылку и понятный лицензионный статус.

## Единая схема именования

Используются строчные латинские буквы, цифры и дефисы. Пробелы, кириллица, служебные последовательности вида `#U041...` и неоднозначные сокращения в новых именах файлов не допускаются.

| Тип | Шаблон | Пример |
|---|---|---|
| Исходный документ | `source-<document-type>-<short-title>.docx` | `source-rpd-b1-v-06-modern-computer-vision.docx` |
| Baseline | `baseline-labNN-<short-topic>.ipynb` | `baseline-lab01-viola-jones.ipynb` |
| Стартовый ноутбук | `labNN_<short_topic>.ipynb` | `lab06_vit.ipynb` |
| КИМ лабораторной | `kim-NN-labNN.md` | `kim-03-lab03.md` |
| Приложение | `appendix-NN-<short-title>.<ext>` | `appendix-01-dataset-card.pdf` |
| Рубрика | `rubric-NN-<short-title>.md` | `rubric-01-project.md` |

При переименовании обязательно обновляются все относительные ссылки, `README.md` соответствующего каталога и `repository-tree.txt`.

## Лицензирование

Перед добавлением стороннего или исходного файла укажите его правообладателя и лицензию. Файл нельзя объявлять распространяемым по CC BY 4.0 только на основании того, что он находится в этом репозитории. Для исходных DOCX используется отдельная таблица статуса в [`docs/source/README.md`](docs/source/README.md).
